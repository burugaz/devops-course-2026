# Сравнение Git и SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?
- **Git:** Ветка — это просто лёгкий указатель (ссылка) на коммит. Создание ветки не копирует файлы, а лишь создаёт новый текстовый файл-указатель размером ~40 байт. Это происходит мгновенно.
- **SVN:** Ветка — это физическая копия директории на сервере. Даже с оптимизациями ("lazy copy") операция требует обращения к центральному серверу и создания метаданных для каждого файла, что при больших репозиториях занимает время.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
**Нет.** SVN — централизованная система (CVCS). История хранится только на сервере. Локальная копия содержит лишь рабочие файлы. Команда `commit` отправляет данные напрямую на сервер, поэтому без сети она невозможна. В Git каждый клон — полноценный репозиторий с полной историей.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
1. **GameDev и CAD:** Работа с огромными бинарными файлами (текстуры, модели). SVN нативно поддерживает lock-механизм (блокировка файла одним пользователем), предотвращая конфликты слияния бинарников.
2. **Частичная выгрузка (Sparse Checkout):** Возможность скачать только нужную подпапку из гигантского репозитория без сложной настройки.
3. **Legacy-проекты и госсектор:** Старые системы, где миграция рискованна или слишком дорога.
4. **Тонкие права доступа:** Гибкая настройка прав на уровне отдельных папок через серверные конфиги (в Git доступ обычно даётся ко всему репо).
